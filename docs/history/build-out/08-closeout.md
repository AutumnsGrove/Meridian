# Stage 8: Close-out

The build is forward-looking: "what do I build next". Once it is built, the repo must be
maintenance-looking: "how do I change this safely". These last tasks make that switch, so the project
does not carry a to-do list for work that is finished. Decision #69.

## T38 Review brief

The owner will run a whole-codebase review with a stronger model after the build. Make that review
cheap and sharp by writing `docs/REVIEW-BRIEF.md` (a durable document; it survives T39):

- The **hard constraints** from CLAUDE.md, each paired with how to check it by hand and the test that
  enforces it mechanically (invariants test rule names, compose invariants).
- The **trust boundaries**, one paragraph each: browser to gateway, probe to upstream, container to
  inbox, inbox to executor, executor to subprocess, host probe to snapshot. For each: what is
  untrusted, where it is validated, and the fuzz target that covers it.
- The **list of fuzz targets** and the property each asserts (generated by grepping `Fuzz*`; do not
  hand-maintain).
- The **decisions most likely to be quietly eroded** (#10, #14, #15, #38, #52, #63) and what erosion
  looks like in a diff.
- **Known sharp edges**: the Ivy `Host` header, `network_mode: host` widening, anyone on the tailnet can
  press the buttons, sudo `NOPASSWD: ALL` for the deploy user (CONTROL.md caveats).
- Suggested review lanes (security of `hostexec`; config and probe correctness; frontend a11y and
  contract; deploy and CI) so the owner can fan a review out.

Also record the output of `scripts/check all`, the fuzz run times used in CI, and the number of fuzz
targets, so a reviewer can tell when coverage dropped.

**Done when**: the brief exists, every claim in it links to a test or a doc line, and it contains no
reference to build-out task numbers (they are about to disappear).

## T39 Maintenance rewrite

Last task of the build. Do it in this order, one small commit per step:

1. **Archive the scaffolding.** Move `docs/PLAN.md` to `docs/history/PLAN.md` and `docs/agent/`
   (including `HANDOFF.md` and the session table) to `docs/history/build-out/`, each with a one-line banner at the top ("Historical: the plan this
   project was built from. Not maintained."). Move resolved entries of `OPEN-QUESTIONS.md` into
   DECISIONS.md (they should already be there) and reduce OPEN-QUESTIONS.md to its empty template.
   Fix every link that pointed into the moved files. Delete nothing else; git history keeps the rest.
2. **README.md**: replace "Status: planning / scaffolding" with a real status; add install, update, and
   "bring your own services" quick starts that match what exists. Remove future tense for things that
   now exist ("planned", "will").
3. **CLAUDE.md** and **AGENTS.md**: drop "Status: planning", the Phase language, the "read these first"
   order built for a greenfield, and the escalation rules aimed at the build. Rewrite them for
   maintenance:
   - the unchanged hard constraints and standards pointer;
   - "how do I...": add a service (config only, `meridian doctor`), add a probe or vital kind (one row
     in `config.HealthKinds`/`VitalKinds`, one runner, tests, the example config, the registry sync
     test fails until all agree), add a control target (the CONTROL.md checklist), cut a release,
     handle a Dependabot update, triage a fuzz crasher (commit it under `testdata/fuzz`, red-green fix);
   - the loop for a single change: test first, small commits, `scripts/check`, docs and decision log;
   - drop the session/handoff ritual (there is no build to resume), but keep the working style: a
     focused change per session, small commits, ask the owner with the question tool only when a
     decision is theirs.
4. **Reference docs** (`ARCHITECTURE.md`, `CONTROL.md`, `DESIGN.md`, `INTEGRATIONS.md`, `STANDARDS.md`):
   read each against the code and fix drift. Remove sentences describing intent now that behaviour
   exists ("Nothing parses them yet", "Phase 1 will..."). In DECISIONS.md do **not** edit entries; append
   a final dated note listing the reversals, if any occurred.
5. **Generated vocabulary docs.** Add `meridian docs kinds` (prints the kinds tables from
   `config.HealthKinds`/`VitalKinds`) and a test that the vocabulary section of `config.yaml.example`
   matches its output, so the example cannot rot. Reference it from the README.
6. **Homelab repo checklist (PLAN Phase 5)**: write `docs/homelab-followups.md` with the exact list for the
   other repository (Meridian section in its README, `docs/meridian.md`, Ivy documentation,
   healthcheck additions). That repository is not edited from here.
7. **Verify**: run a link checker over `*.md`, `scripts/check all`, and read the README top to bottom as a
   stranger would. Anything that still says "build-out", "Phase 0..5", or a `T##` id is a bug.

**Done when**: `grep -rEn "T[0-9]{2}|S[0-9]{1,2}\b|HANDOFF|build-out|Phase [0-5]" --include=*.md . | grep -v docs/history`
returns nothing, the README matches reality, and `AGENTS.md` describes maintaining the project rather
than building it.

## T40 Optional: PR review workflow with Pi and OpenRouter

The owner wants a review workflow for the maintenance era (once changes arrive as pull requests).
This is deliberately not part of the build.

- `.github/workflows/review.yml` on `pull_request` (**never** `pull_request_target`; fork PRs get no
  secrets and the job must tolerate that by skipping), `permissions: contents: read, pull-requests:
  write`.
- Runs the Pi agent with an OpenRouter key from the repository secret `OPENROUTER_API_KEY`, using a
  prompt kept in `.github/review-prompt.md`. The prompt must instruct the reviewer to check the diff
  against `docs/REVIEW-BRIEF.md` and `docs/STANDARDS.md`, to report only concrete findings with a
  file and line, and to say nothing when there are none.
- Pin Pi and any action by version/SHA; the job must not have write access to repository contents,
  must not echo the key, and must treat the PR text and diff as untrusted input (it cannot change its
  own instructions or run PR-supplied code).
- Cap cost: skip drafts and PRs touching only docs; limit diff size sent to the model.
- `[human]` The owner adds the secret and decides the model. Until then the workflow file stays out
  of the repo or disabled.

**Done when**: the workflow lints clean with `actionlint`, and a throwaway PR gets exactly one review
comment (or none) from it.
